## How to verify a redeploy (what went wrong at 00:40, and the exact steps)
**Two different things exist:** the code in the editor, and the *deployment* — the frozen version phones actually run.
- Running a function from the editor (`testVipAlertTemplate`, `vipAlertReport`) always uses the **code you just saved** — that's why those worked at 12:42.
- The web app URL runs a **numbered version**. Your Manage-deployments screen still said **Version 4 on Sep 19, 5:08 PM**, so nothing changed for the phones.
  ("Deployment successfully updated" appears even when you click Deploy on the *same* Version 4.)

**Do this:** Deploy → **Manage deployments** → click the ✏️ pencil on the deployment → open the **Version** dropdown → choose **New version** → **Deploy**.
It worked if the dialog now says **Version 5 (or higher) on Sep 20, 2026** — a new number and today's date. The Deployment ID and URL stay the same.

**What `?action=ping` means:** it's just text added to the end of the web address. Paste this into a browser tab:
`https://script.google.com/macros/s/AKfycbyUZywdnh62McTK-FJwHlu5ltnrzWI6dnc1v1HMxNwG2PPM1vJO-xsXCz5T-rNrVPVi/exec?action=ping`
- New version is live → the page shows `{"status":"SUCCESS","message":"pong","version":"2026-09-20.1",…}`
- Old version → `{"status":"ERROR","message":"Unknown action."}`

**You no longer have to do this by hand:** the scanner now calls `ping` itself. If the deployed script is old it shows a **red dot on the ⚙️** and a warning at the
top of Settings; when it's current, Settings shows `backend 2026-09-20.1`.
